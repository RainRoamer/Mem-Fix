# 项目工作交接

轻量模板：替换填写说明，保留以下五项即可。复杂任务按需添加扩展栏目，删除不需要的空表；代码路径使用项目相对路径。

## 目标

- 任务 ID：项目内唯一的任务标识，接续同一任务时保持不变。
- 目标与验收条件：当前要完成的具体结果，以及判断完成的依据。
- 要求来源：引用项目规则或需求文档；只补充当前任务必要的范围边界。

## 当前状态

- 任务状态：进行中 / 待确认 / 已暂停 / 已完成 / 已取消，选择实际状态。
- 检查点 ID：如 CP-import-0001；每次产生新快照时递增，沿用项目已有编号也可。
- 更新时间及时区：使用实际可取得的时间，无可靠时钟时明确说明。
- 项目与版本：项目根目录、分支和 HEAD；无 Git 或无提交时明确说明。
- 当前停点与代码可用性：已完成到哪里、是否可运行；未知则记未验证。
- 阻塞或恢复条件：仅在有阻塞、暂停或取消时填写实际原因与恢复依据。

## 改动

- 本任务改动：涉及文件、实际结果和尚未完成部分。
- 相关未提交文件状态与归属：暂存、未暂存、未跟踪或删除情况；不能确认归属时写来源未知。
- 必须沿用的决定：有关键决定才写结论、简要依据和确认来源；不要把模型选择标为用户确认。

## 验证

每条实际检查写一行：验证 ID、关联检查点 ID、执行目录与命令、实际结果与范围、当时 HEAD、相关文件状态，以及指纹或证据路径。低影响任务未采集指纹时明确写“未采集”。未执行的检查写明原因。

验证后发生相关修改时标记待重验；当前记录可以引用旧验证，不能把它记成新执行。文件哈希或提交号不代表已经通过测试。

## 下一步

写能够直接执行的动作、涉及文件与完成判据。待确认或已暂停任务说明恢复所需条件；已完成或已取消任务写“无自动续做事项”，旧建议只作参考，不作为新任务授权。
