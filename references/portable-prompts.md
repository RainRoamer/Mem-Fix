# 跨模型启动与接手提示词

这些提示词用于激活和延续 Mem-Fix。它们不依赖专用模型能力。先让模型读取 `SKILL.md`；普通聊天工具没有 Skill 加载机制时，把其正文作为用户指令提供，再提供项目规则、交接记录和必要代码。

`$mem-fix` 只适用于支持且已经发现该 Skill 的工具；其他工具使用下列完整文本，不假定它理解这个名称。本文中的默认路径应替换成项目实际约定。

## 1. 首次建立项目连续性

```text
请按 Mem-Fix 流程为当前项目建立持续开发记录。

先读取我提供或指定的 SKILL.md。确认项目根目录，检查现有项目
规则、需求资料、交接记录及当前相关代码；项目使用 Git 时核对
已有改动。复用已有权威文档和约定，避免建立互相冲突的副本。

没有现成约定时，在项目 AGENTS.md 中加入连续性区块，并建立
docs/HANDOFF.md。保留原有文件内容，不把 Skill 模板中的示例、
填写说明或模型猜测当成项目事实。

登记可追溯的用户要求、当前目标与验收条件、已采用决策及依据、
现有进度、验证状态和下一步。无法确定的内容明确标为未知或
待验证，不声称用户确认过没有证据的决定。

默认使用轻量格式，记录任务 ID、任务状态与检查点 ID；需求或
决策较多时才展开。确有并行任务时，各自使用独立交接文件。

如果我已经给出开发任务，建立记录后继续该任务，按检查点更新；
如果我只要求建立记录，就在完成记录后结束，不扩大到产品改动。
没有文件访问能力时，基于提供的材料输出完整记录，并说明尚未落盘。
```

## 2. 换模型、新对话或中断后的接手

```text
请接续当前项目，并按 Mem-Fix 流程工作。

先读取我指定或提供的 SKILL.md、项目 AGENTS.md、
docs/HANDOFF.md，以及本任务需要的代码和权威需求资料。
项目使用 Git 时检查当前分支、状态及相关 diff，核实记录是否过期。

先确认任务 ID 和状态。已完成或已取消任务的旧下一步不自动执行；
已暂停任务按用户当前恢复指令处理，不把普通结束一轮当成暂停。

简短说明当前目标与验收条件、必须沿用的要求和设计决定、
已完成与未验证内容，以及准备执行的下一步，然后继续工作。

区分用户要求、已采用决策、代码事实与待验证建议。不要仅因个人
偏好重写已有架构或重复实现已有功能；证据表明旧方案有问题时，
说明影响和最小修正方案，在已授权范围内处理。

用户明确提出的新要求应同步更新。常规实现选择自行判断；
只有缺失信息或要求冲突实质影响正确性、范围或核心设计时，
才提出具体问题，并继续不依赖该答案的工作。

每完成一个可验证步骤、开始复杂改动、遇到阻塞或调整方案后，
更新交接记录；结束本轮项目工作前补齐实际变化。
不得把旧版本的测试结果当成当前代码已经通过。
每条验证对应检查点 ID、当时 HEAD 和相关工作区状态；关键验证
采集相关文件指纹，避免同一 HEAD 下未提交修改造成混淆。

没有文件工具时，使用我提供的文档和代码，明确未核对的范围，
输出新版完整交接记录供我保存，不声称已经读写本地文件。
```

## 3. 切换前保存检查点

```text
请现在保存 Mem-Fix 交接检查点。

核对当前代码、已有 diff 和已经执行的验证，更新
docs/HANDOFF.md 或项目约定的等效文件。记录当前目标、有效要求、
关键决策及依据、已完成与进行中内容、最近可验证状态、
未提交改动的已知归属、阻塞及下一步动作和完成判据。

区分已修改、已验证、已完成。没有执行的检查写未验证。
删除过期进度，保留仍有效的约束和未关闭问题；保存前重读文件，
合并其他更新。不要顺带改产品代码、提交、推送或部署。

使用 Mem-Fix 保存脚本时，先获取旧文件哈希，再写独立候选文件，
由脚本核对冲突、同目录替换并保留上一份快照；不要先改正式文件。
检查点使用新编号，任务状态据实记录，结束本轮不等于暂停任务。

保存成功后给出文件路径和当前恢复位置；无法写文件时，
直接输出可复制的完整交接记录，并明确尚未落盘。
```

## 4. 只复核是否偏离原要求

```text
请根据项目规则、权威需求和当前交接记录，复核当前实现
是否偏离有效要求或已采用的设计决定。

用代码位置、差异或现有验证结果说明发现；区分确定违反、
证据不足与允许范围内的实现差异。用户已改变的要求不要继续
按旧版本判断，也不要仅因个人偏好把已有设计判为错误。

本次先给出有依据的复核结果与最小修正建议，不自动修改产品代码。
```
