# 验证与代码状态绑定

交接检查点和代码指纹解决不同的问题。检查点编号区分交接记录版本；代码指纹区分同一 HEAD 上的多次未提交修改。二者都不是代码备份，不能据此自动回滚文件。

## 固定字段

每份交接顶部写明 `任务 ID`、`任务状态`、`检查点 ID`；检查点编号建议使用 `CP-<task-id>-0001` 并递增，也可沿用项目已有方式。

每条实际执行的验证使用以下字段，可放在一行或表格中：

| 字段 | 内容 |
| --- | --- |
| 验证 ID | 任务内唯一，例如 `V-import-001` |
| 检查点 ID | 记录该结果的交接检查点；新检查点可引用旧验证，但不能假装重新执行过 |
| 命令与目录 | 实际执行的命令或手动检查，以及工作目录 |
| 结果 | 成功、失败、未执行或代码变化后待重验；写明验证范围 |
| HEAD | 实际提交标识；无提交、无 Git 或不可取得时明确说明 |
| 相关工作区状态 | 检查过的文件路径与 Git 修改状态，包含未跟踪、暂存和未暂存变化 |
| 代码指纹 | 关键验证记录相关文件的 SHA-256 或脚本输出 `state_id` 及证据位置；没有则写“未采集” |

只记录“HEAD 一样”或“这些文件都是 M”不能证明文件内容没变。没有指纹时，通过实际 diff 与必要重验确认，不将当前状态视作精确匹配。

## 可选指纹工具

使用 [checkpoint.py](../scripts/checkpoint.py) 的 `state` 命令生成只包含文件路径、哈希和 Git 状态的 JSON。必须列出实际相关的源文件、测试、配置或锁文件；不读取整个仓库或所有敏感文件。

```text
python "<skill>/scripts/checkpoint.py" state --root "<project>" --path "src/import.py" --path "tests/test_import.py" --path "pyproject.toml"
```

`--path` 接受项目相对文件路径，可重复；目录、项目外路径及符号链接文件会拒绝，删除或不存在的文件记录 `missing`。没有 Git 时仍可计算文件哈希，输出明确说明 Git 信息缺失。

在关键验证前后使用相同路径集各采集一次。如果 `state_id` 不同，结果不能归属于一个稳定状态；查明是代码、暂存状态或验证生成文件变化，重新选择范围或重验，不能宣称“当前版本已通过”。保存完整 JSON 到项目约定的证据位置，例如 `docs/handoffs/evidence/<task-id>-V001.before.json` 和 `.after.json`；也可将少量字段直接写入交接。

采集仅逐个读取指定文件，不是全仓库事务快照。前后相同也不覆盖未列入的依赖、运行环境、外部服务或期间变化后又还原的文件。记录验证环境中确实影响结果的因素，避免夸大证据范围。

交接文件、候选文件和指纹输出本身不应加入代码路径集，以免记录更新造成自指变化。脚本采集后仍须检查命令实际返回值，失败时不能使用空输出作为指纹。

## 轻量使用

小任务在“验证”一栏写上述必要事实即可，无须建立新表格或额外证据文件。低影响文档修改可记录检查命令、HEAD、相关文件状态，并明确“代码指纹未采集”。只有需要精确绑定的关键验证使用文件哈希。
